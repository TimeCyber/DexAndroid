# 大麦「本地登录 → 选场次 → 选座 → 下单」完整流程

> 基于 `选座下单流程接口文案.md` + `API文档.md` 整理。  
> 在选座下单主链前补上**账号登录 / 会话准备**，形成可按步骤对照的本地业务流程。  
> 不包含可直接调用的请求体、签名、Cookie 拼装方式；以接口职责与顺序推断为主。

---

## 一、整体流程（一句话）

先完成**本地登录拿会话**，再选定项目与场次，拉座位图并预检，接着**算价 → 构建订单 → 创建订单 → 取支付参数 → 支付完成回调**。

```text
[登录/会话] → [项目/场次] → [座位图+状态] → [选座预检] → [算价]
       → [构建订单] → [创建订单] → [支付参数] → [支付完成]
```

**硬前提：** 从阶段 3（算价）起、尤其 `trade.order.create`，请求必须已带有效登录态（Cookie / sid / token 等）；未登录会在确认页或 create 阶段失败。

---

## 二、阶段 0：本地登录 / 会话准备

本地跑通下单前，先建立与 App 一致的账号会话。dump 中可见多套登录入口，按「冷启动 → 登录 → Token/Cookie → 大麦侧鉴权」理解即可。

### 0.A 启动与预登录

| 步骤 | 接口名 | 文案说明（职责推断） |
| --- | --- | --- |
| 0.1 启动信息 | `mtop.com.taobao.mloginService.appLaunch` | App 启动时拉取登录相关配置 |
| 0.1' | `mtop.com.taobao.mloginService.getAppLaunchInfo` | 启动信息变体 |
| 0.2 预登录信息 | `mtop.com.taobao.mloginService.prelogininfo` | 登录前环境/能力探测 |
| 0.3 登录分流 | `mtop.taobao.mloginService.getLoginFlow` | 决定走短信/密码/SSO/生物等哪条流 |

### 0.B 主动登录（任选其一，以实际抓包为准）

| 步骤 | 接口名 | 文案说明（职责推断） |
| --- | --- | --- |
| 0.4 账密登录 | `mtop.mloginService.login` / `mtop.taobao.alibabaMLoginService.login` | 主登录 |
| 0.4' 短信登录 | `mtop.taobao.mloginService.smsSend` → `smsLogin` | 发码再验码登录 |
| 0.4'' Token 登录 | `mtop.mloginService.mloginTokenLogin` / `alibabaMLoginService.mloginTokenLogin` | 已有 token 换会话 |
| 0.4''' SSO | `mtop.mloginService.ssoLogin` / `unifyssotokenlogin` | SSO / 统一 token |
| 0.4'''' 自动登录 | `mtop.mLoginUnitService.autoLogin` / `appOldAutoLogin` / `alibabaMLoginService.autologin` | 本地已有凭证时静默续期 |
| 0.5 扫码登录 | `genQrCode` → `scanedQrCode` → `confirmedQrCode` → `qrcodelogin` | 二维码链路（`commonuse.mloginService.*`） |

### 0.C 会话落盘 / 大麦侧 Token

| 步骤 | 接口名 | 文案说明（职责推断） |
| --- | --- | --- |
| 0.6 Cookie | `mtop.login.getAlipayCookies` / `mtop.login.getWapLoginCookies` | 登录后拉 Cookie，供后续 mtop 带上 |
| 0.7 SSO Token | `mtop.mLoginTokenService.applySsoToken` / `applySsoTokenV2` | 申请/刷新 SSO |
| 0.8 大麦 Token | `mtop.damai.mxm.user.token.get` | 大麦侧用户 token |
| 0.9 AccessToken | `mtop.damai.mxm.user.accesstoken.get` | 大麦侧 access token |
| 0.10 登出（可选） | `mtop.taobao.alibabaMLoginService.logout` / `havana.mlogin.logout` | 清会话 |

**本阶段产出（逻辑上）：**  
有效 `sid` / Cookie / 大麦 `token` / `accessToken`；后续所有业务 mtop 请求复用该会话。

**对应文案：**  
「本地先登录成功 → 拿到 Cookie/Token → 再进入项目与下单链。」

**本地操作建议（流程级，非实现细节）：**

1. 用真实账号在 App/登录页完成一次登录（或自动登录续期）。  
2. 确认后续 mtop 请求已携带登录态。  
3. 会话失效时回到 0.B/0.C，不要直接重试 create。

## 九、主路径时序（登录 + 下单，推荐阅读版）

```text
⓪ 本地登录 / 会话
   └─ appLaunch / prelogininfo / getLoginFlow（可选）
   └─ mloginService.login（或 smsLogin / mloginTokenLogin / autoLogin）
   └─ getAlipayCookies / getWapLoginCookies（按需）
   └─ mtop.damai.mxm.user.token.get
   └─ mtop.damai.mxm.user.accesstoken.get
   → 本地持有有效登录态

① 选定项目
   └─ mtop.damai.item.detail.getdetail
   └─（可选）performance.calendar.get / project.get*AreaInfo

② 选择场次 performId
   └─ chooseSeatParam → dynamicInfo → queryperformseatstatus → querypricecolor
   → 弹出座位图

③ 点选座位
   └─ seat.precheck
   └─ calcTicketPrice
   └─（可选）calcOrderPromotion

④ 确认订单（会话必须有效）
   └─ trade.order.build
   └─（改信息）trade.order.adjust

⑤ 提交下单
   └─ trade.order.create
   └─（或）wireless.trade.common.order.create / spliceorder.create

⑥ 支付
   └─ paymentwaylist → getpayparam / orderpayparam
   └─ 渠道支付
   └─ paymentCompletion
```

## 十、本地联调检查清单

按顺序自检，缺哪步补哪步：

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1 | 登录是否成功 | 0.B 有成功响应，本地有 sid/Cookie/token |
| 2 | 大麦 Token | `mxm.user.token.get` / `accesstoken.get` 可返回 |
| 3 | 项目详情 | `getdetail` 能拿到场次/票档 |
| 4 | 座位图 | `queryperformseatstatus` + `dynamicInfo` 有数据 |
| 5 | 预检 | `precheck` 通过 |
| 6 | 算价 | `calcTicketPrice` 有金额 |
| 7 | 建单 | `build` 出确认页组件 |
| 8 | 落单 | `create` 返回 orderId（失败优先查会话是否过期） |
| 9 | 支付 | `getpayparam` 有渠道参数，完成后再 `paymentCompletion` |

## 十二、局限
